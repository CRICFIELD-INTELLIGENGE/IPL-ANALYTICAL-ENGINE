# 27 — Design Portfolio Readiness

> A UI/UX or product-design portfolio case study is judged on **process evidence** (problem framing, research, iterations, testing, outcomes), not only on the final screens. The repository contains final screens (code) and some engineering process documents, but **no Figma files, wireframes, research notes, usability results, design-iteration artefacts or accessibility audits**.

## 2. Minimum artefact set per case study

1. Problem statement and target user (1 page).
2. Research: 5 interviews or a survey with ≥ 30 responses; synthesis board.
3. Information architecture / user flow diagram.
4. Low-fi wireframes (2 alternatives) → mid-fi → high-fi in **Figma**, with components and variants.
5. Usability test: 5 participants, task success, time, quotes.
6. Iteration: what changed and why.
7. Accessibility check: contrast, keyboard, screen reader spot-check.
8. Outcome: before/after metrics (even if only test metrics) and what you would do next.

## 3. Claims you can and cannot make today

| Can say | Cannot say (yet) |
|---|---|
| “I set the visual direction and product scope for CricField and directed its implementation with AI assistance.” | “I designed CricField in Figma.” |
| “I designed an interface that shows sample size and confidence intervals next to rankings.” | “Users found the rankings trustworthy.” |
| “I ran an expert heuristic audit and an accessibility review of my own product.” | “The site is accessible.” |
| “I redesigned the Dugout squad views (carousel, grid, table).” | “The redesign improved engagement.” |

## 4. Fastest path to one portfolio-grade case study (4–6 weeks)

Pick **Scout Lab**. Week 1: interview 5 people who scout or coach. Week 2: Figma rebuild of the leaderboard + profile; fix sort/role/CI labels. Week 3: usability test 5 users on 5 tasks. Week 4: iterate, accessibility pass, write-up with before/after.
